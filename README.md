# Видеофабрика

Телеграм-бот, который делает короткие видео от идеи до публикации на YouTube:
сценарий → кадры → озвучка → монтаж с субтитрами → загрузка на канал.

Форматы из коробки: ИИ-истории, детские сказки, факты/топы, крипи-истории.

## Как это работает

```text
/new в телеге  ─►  очередь (SQLite)  ─►  воркер
                                          │
        1. Сценарий      Gemini (текст)   │  JSON: заголовок, описание, теги,
                                          │  сцены (текст диктора + промпт кадра)
        2. Озвучка       Gemini TTS       │  wav на каждую сцену, длительность
                                          │  сцены = длительность её озвучки
        3. Кадры         Gemini Image     │  картинка на сцену
                         или Veo          │  (или готовый видеоклип)
        4. Монтаж        ffmpeg           │  кадр под каждую озвучку, плавный
                                          │  зум, субтитры, фоновая музыка
        5. Публикация    YouTube API      │  приватно / по ссылке / публично
                                          ▼
                              видео в чат + ссылка на ролик
```

Пайплайн живёт в `pipeline/`, каждый шаг — отдельный файл.

## Установка

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Отдельно нужен **ffmpeg** (сам монтаж): скачать с ffmpeg.org и добавить в PATH,
либо прописать путь в `FFMPEG_BIN` / `FFPROBE_BIN`.

## Ключи

Скопируй `.env.example` в `.env` и заполни:

1. `TELEGRAM_BOT_TOKEN` — у @BotFather.
2. `TELEGRAM_ADMIN_IDS` — свой Telegram ID (бот ответит им на `/start`, если ID не в списке).
3. `GEMINI_API_KEY` — Google AI Studio.
4. YouTube: в Google Cloud Console включи **YouTube Data API v3**, создай
   OAuth client (тип Desktop), впиши `YOUTUBE_CLIENT_ID` и `YOUTUBE_CLIENT_SECRET`,
   потом один раз запусти `python auth_youtube.py` и вставь выданный
   `YOUTUBE_REFRESH_TOKEN` в `.env`.

## Запуск

```powershell
python main.py
```

Один процесс поднимает три вещи: телеграм-бот, воркер очереди и планировщик автопостинга.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/new` | мастер: формат → тема → тип визуала → что делать с готовым |
| `/queue` | что в работе и последние ролики |
| `/job N` | карточка задачи: статус, файл, ссылка, ошибка |
| `/cancel N` | отменить задачу |
| `/auto on\|off` | автопостинг по расписанию |
| `/settings` | текущие модели и параметры |
| `/yt` | проверить, что канал подключён |
| `/voices`, `/models` | список голосов и доступных моделей |

Тему можно прислать своими словами или нажать «Придумай сам» — тогда Gemini
предложит 5 идей кнопками.

## Режимы визуала

| Режим | Что делает | Цена |
| --- | --- | --- |
| `flow` | Veo через веб-интерфейс Flow на подписке Google AI Pro | по подписке |
| `image` | картинка на сцену + плавный зум (эффект Кена Бёрнса) | дёшево |
| `veo` | видеогенерация Veo через платный API | дорого |
| `gradient` | градиентные заливки вместо картинок | бесплатно, для тестов |

Запасной вариант выбирается **на весь ролик сразу**, а не на отдельную сцену:
иначе в одном видео смешались бы клипы Veo и статичные картинки. Перед стартом
бот считает, хватит ли на ролик оставшихся генераций Flow, и если нет — либо
делает весь ролик картинками, либо (`FLOW_STRICT=true`) честно валит задачу.

Если исходный клип короче озвучки, последний кадр замирает — не отматывается
на начало.

## Flow через браузер

Подписка Google AI Pro не даёт квоту API — она даёт доступ к Flow в браузере.
Поэтому режим `flow` водит настоящий Chromium по живой сессии: логинишься руками
один раз, дальше бот ездит на сохранённом профиле.

```powershell
python -m playwright install chromium
python login_flow.py --acc acc1        # логинишься, окно закрывать не надо
python login_flow.py --acc acc1 --inspect   # покажет селекторы страницы
python login_flow.py --acc acc1 --probe "cinematic shot of a lighthouse"
```

Профили лежат в `profiles/<имя>`, аккаунты перечисляются в `FLOW_ACCOUNTS`.
Бот берёт следующий живой аккаунт, считает расход за сутки (`FLOW_DAILY_LIMIT`)
и убирает аккаунт в блок на `FLOW_BLOCK_MINUTES` при ошибке. Расход показывает
команда `/flow`.

Вёрстку Flow переписывают, поэтому селекторы вынесены в `.env`
(`FLOW_PROMPT_SELECTOR`, `FLOW_SUBMIT_SELECTOR`) — чинится правкой конфига, а не
кода. Готовое видео ловится по сетевому ответу (`FLOW_VIDEO_PATTERN`), а не по
вёрстке, так что переживает редизайн. При сбое с `FLOW_DEBUG=true` в `logs/flow`
кладётся скриншот и html страницы.

`FLOW_HEADLESS` держи в `false`: headless-браузер палится.

## Длина ролика

Выбирается кнопкой в `/new`:

| Вариант | Сцен | Зачем |
| --- | --- | --- |
| ~10 сек | 1 | один клип Flow на ролик, основной формат |
| ~30 сек | 3 | три клипа |
| ~60 сек | 6 | полноценный Shorts |

Для односценного ролика сценарий пишется по отдельному промпту: одна законченная
мысль с панчем в конце, без разгона и без «подпишись». Восемь секунд на сцену —
ровно столько длится клип Veo, чтобы кадр не пришлось тянуть.

## Автопостинг

```env
AUTO_ENABLED=true
AUTO_TIMES=10:00,19:00
AUTO_PRESET=ai_stories
AUTO_PRIVACY=private
AUTO_NOTIFY_CHAT_ID=123456789
```

В указанное время бот сам придумывает тему (сверяясь с последними 30, чтобы не
повторяться), гонит её через пайплайн и заливает на канал, а в чат присылает
готовый ролик и ссылку.

## Файлы

```text
├─ main.py            запуск: бот + воркер + планировщик
├─ bot.py             команды, кнопки, уведомления
├─ config.py          все настройки из .env
├─ storage.py         SQLite: очередь задач и настройки
├─ prompts.py         пресеты форматов и промпты
├─ ai.py              Gemini: текст, картинки, озвучка, Veo
├─ flow.py            Chromium-сессии Flow, пул аккаунтов и лимиты
├─ login_flow.py      разовый логин, отладка селекторов, пробный прогон
├─ youtube.py         загрузка на канал
├─ auth_youtube.py    разовое получение refresh token
├─ scheduler.py       автопостинг по времени
└─ pipeline/
   ├─ script.py       сценарий из темы
   ├─ voice.py        озвучка сцен
   ├─ visuals.py      кадры (Veo / картинки / градиент)
   ├─ subtitles.py    ASS-субтитры с таймингом по сценам
   ├─ assemble.py     ffmpeg: клипы, склейка, музыка
   ├─ media.py        обёртки над ffmpeg/ffprobe
   └─ runner.py       оркестратор шагов и воркер очереди
```

## Что учтено

- Задачи переживают рестарт: незавершённые возвращаются в очередь.
- `/cancel` проверяется между шагами, задача останавливается на ближайшем.
- Видео больше 48 МБ не отправляется в чат — бот присылает путь к файлу.
- Вертикальные ролики автоматически получают `#Shorts` в описании.
- Детский пресет выставляет `madeForKids` при загрузке.
- Обложка ставится, если канал верифицирован; иначе ошибка проглатывается.

## Подводные камни

- **Refresh token протухает за 7 дней**, пока OAuth-приложение в статусе *Testing*.
  В Google Cloud Console → OAuth consent screen нажми **Publish app**, тогда токен живёт постоянно.
- **Квота YouTube API — 10 000 единиц в сутки**, одна загрузка стоит ~1600.
  Это примерно 6 роликов в день с одного проекта. Больше — запрашивать увеличение квоты.
- Veo тарифицируется по секундам сгенерированного видео, поэтому режим `veo` держи
  для отдельных роликов, а поток гони в режиме `image`.
- YouTube плохо относится к массовому однотипному ИИ-контенту без ценности:
  для монетизации нужны разные темы, нормальные заголовки и хоть какая-то авторская подача.
